# design-sync notes — Bugler

- This is an app repo, not a packaged DS. The design surface is `frontend/src/components/ui/` (shadcn-style primitives). No library build exists — the converter runs in synth-entry mode; `--entry` must point at a non-existent path under `frontend/` (e.g. `frontend/dist-ds/index.js`) purely so PKG_DIR resolves to `frontend/`.
- `srcDir` is scoped to `src/components` deliberately: default `src/` would `export *` the whole app (routes, pages, API client) into the bundle.
- Compound sub-parts (CardHeader, SelectTrigger, …) are bundle exports but intentionally NOT separate cards — the 8 cards come from `componentSrcMap` pins; sub-parts are documented in the parent's doc.
- `Combobox` + `FilterChip` (added 2026-07-28) are hand-rolled kit primitives, not Radix. Combobox's dropdown is absolutely positioned (no portal) and opens via focus — its previews use `autoFocus` to render the open state, and the component mirrors Select's `cardMode: "single"` override (`primaryStory: "OpenWithKeys"`).
- CSS: Tailwind v4 source CSS isn't browser-consumable. `frontend/ds-css/build.ts` (bun + the repo's own bun-plugin-tailwind) compiles `frontend/ds-css/entry.css` → `frontend/.ds-css/entry.css` (= `cfg.cssEntry`). The entry `@source`-scans `frontend/src` AND `.design-sync/previews`, so **re-run `buildCmd` after authoring/editing previews** — otherwise preview utility classes are missing from the compiled CSS.
- Tokens: brass theme in `frontend/styles/globals.css` (hex, light "warm paper" + `.dark` "navy console"; since 2026-07-27, replacing the original neutral oklch theme). Fonts: IBM Plex Sans/Mono via a remote Google Fonts `@import` at the top of globals.css — it survives the CSS compile and ships in the `styles.css` closure; `[FONT_REMOTE]` is the expected diagnostic, `[FONT_MISSING]` is not.
- Playwright: machine cache has chromium-1234 (`%LOCALAPPDATA%/ms-playwright`); repo's `e2e/` pins `@playwright/test ^1.62.0`.
- `FilterSelect` (frontend/src/features/explore) is app-level glue over Select — excluded from the DS by user scope decision (2026-07-27).
- Converter deps in `.ds-sync/`: pin `typescript@5` — `typescript@latest` resolves to the v7 (Go) rewrite whose package no longer exports the old compiler API, which silently skips validate's `.d.ts` parse check. `playwright@1.62.0` matches the cached chromium-1234 and the repo's e2e pin.
- Windows: `package-build.mjs` can hit a transient `EPERM: rm ds-bundle` (lingering chromium/AV handle). Just retry — second run succeeds.
- `Select` uses `cfg.overrides.Select = {cardMode: "single", primaryStory: "OpenWithGroups"}` — the open popover portals outside grid cells (`[GRID_OVERFLOW]` escape case). The other stories (Default, FilterBar) remain addressable via `?story=` and in `.review.html`, just not on the card face.
- `frontend/ds-css/entry.css` carries an `@source inline()` safelist of semantic utilities no app source uses as a bare class (`text-foreground` etc.). **Keep it in sync with `.design-sync/conventions.md`** — the conventions validation greps compiled CSS for every named class.
- `--radius-sm/md/lg/xl` are `@theme inline` — compile-time only, never runtime CSS variables. Only `--radius` exists at runtime. Conventions doc reflects this; don't "fix" it back.
- `Dialog` (added 2026-07-28) is vendored shadcn over `@radix-ui/react-dialog` — the 9th primitive, and the first in the `Overlays` group. Overlay → `cfg.overrides.Dialog = {cardMode: "single", primaryStory: "Destructive", viewport: "720x520"}`. Its previews use `defaultOpen` with **no** `DialogTrigger`: Radix portals the content and the modal scrim fills the card, which is what the real dialog looks like. Radix auto-focuses the first field, so the captured cards show a focus ring and selected text in the input — authentic, not a defect.
- `Checkbox` (added 2026-07-28) is vendored shadcn over `@radix-ui/react-checkbox` — the 10th primitive, in the `Forms` group. No `cfg.overrides` entry: it's neither an overlay nor wide. Its four previews (Default / Checked / Disabled / Group) are authored from real Bugler usage — the login form's "Stay signed in" and a severity filter stack.
- **`dark:data-[state=checked]:bg-primary` in `checkbox.tsx` is load-bearing — do not "de-duplicate" it.** `dark:bg-input/30` and `data-[state=checked]:bg-primary` match with the SAME specificity (`:is(.dark *)` contributes one class, as does the `[data-state=checked]` attribute), so the compiled source order decides — and the `dark:` variant lands later (index ~53185 vs ~51422 in the app CSS). Without the explicit dark override the checked box renders with no brass fill in dark mode, which is the default theme. Verified after the fix: dark → `#E9A43C` fill / `#1B1204` glyph, light → `#B26E0E` / `#FFF8EC`. Any shadcn regeneration will drop this class again.
- Reading computed styles from a checkbox in headless chromium is unreliable right after a state flip: `getComputedStyle` returns a stale `color` until a style recalc is forced (`el.style.display='none'; void el.offsetHeight; el.style.display=''`). Freshly-created probe elements with identical classes read correctly. Don't diagnose a token bug from an un-forced read — force the recalc first.
- **A `componentSrcMap` name must be an actual export of its file.** `chart.tsx` originally exported only `ChartContainer`, and validate failed with `✗ [BUNDLE_EXPORT] 1/11 not a component on window.Bugler: Chart` — the converter looks up `window.<globalName>.<Name>` verbatim. The root is therefore named `Chart` (matching `Card`, `Dialog`, `Button`) with `Chart as ChartContainer` exported alongside, since that is the name shadcn generates. **A shadcn regeneration of `chart.tsx` drops that alias and renames the root back** — same class of casualty as the checkbox `dark:` class above, and validate does catch this one.
- `Chart`'s render-check `texts` entry contains the CSS that `ChartStyle` injects (`--color-error: …`). That is the `<style>` element's text content being scraped, not visible output — the screenshot is clean. Not a defect; don't chase it.
- `Chart` previews import the Recharts marks **from `bugler-frontend`, not from `recharts`** — `chart.tsx` re-exports `BarChart`, `Bar`, `XAxis`, `YAxis`, `CartesianGrid`, `Cell`, `ReferenceArea` for exactly that reason. A preview that reached for `recharts` directly would depend on how the converter resolves externals, which nothing here pins. Add a mark to that re-export list before using it in a preview.
- `Chart` (added 2026-07-29) is the shadcn Recharts wrapper — the 11th primitive, and the first that pulls a third-party render engine into the kit. `recharts` is a real runtime dep, not vendored source, so a Recharts major is a kit-wide render change. Its series colours come from `chartConfig` → CSS variables, so previews must name **semantic** tokens (`--severity-error-fill`, …), never `--chart-1..5`: the numbered palette is the generic categorical ramp for future dashboards, and pointing severity at it would repaint the logs UI whenever that ramp is retuned.
- Severity colours are tokens as of 2026-07-29 (`--severity-error/-warn/-info/-debug`, each with a `-fill` companion). The plain token is tuned for the 3px rail in a log row; the `-fill` companion is lightened for large filled areas in a chart, where the rail values disappear into the navy background. Both roles are deliberate — do not collapse them back into one.
- `Resizable` (added 2026-07-31) is the shadcn wrapper over `react-resizable-panels` — the 12th primitive, first in the `Layout` group alongside `Card`, and the **second** kit component with a real runtime dep rather than vendored source (after `recharts`). Exported as `ResizablePanelGroup` with `ResizablePanelGroup as Resizable` alongside, because the converter looks up `window.Bugler.Resizable` verbatim — the same arrangement, and the same regeneration casualty, as `Chart`/`ChartContainer`.
- **The panel group writes `height: 100%` on itself inline, so a height utility on the group is dead.** The height has to come from a parent with a definite one. The app is fine (the group is a flex item of a full-height column), but the first draft of `previews/Resizable.tsx` put `h-56` on the group and rendered against an auto-height cell: the two horizontal stories survived on their content and the **vertical story collapsed to a bare line**. Fixed by wrapping each story in `<div className="h-56 w-full">`. Worth remembering because the render check passed both times — a collapsed panel is still a clean render.
- `resync.mjs --node-modules` must point at **`frontend/node_modules`**, not `.ds-sync/node_modules`: the converter vendors React from there and `.ds-sync/` only carries its own toolchain (esbuild/ts-morph/typescript/playwright). Wrong path fails fast in `emit.mjs` with a "react not found" remedy hint.
- `react-resizable-panels` v4 is nothing like the v2 API most references describe: components are `Group`/`Panel`/`Separator`, persistence is `useDefaultLayout` (not `autoSaveId`), **numeric sizes are pixels while bare strings are percentages** (`defaultSize="384"` means 384%), and the separator publishes its interaction state on `data-separator` (`inactive`/`hover`/`active`/`focus`/`disabled`) with `aria-orientation` describing the separator's own axis. Read the installed `.d.ts` before trusting any snippet.
- **The project holds content this sync does not own**: `templates/`, `design_handoff_bugler_ui/`, `uploads/`, `github.md`. Anchored re-syncs are safe (deletes come verbatim from `.sync-diff.json`'s `upload.deletePaths`), but if the anchor is ever lost, the no-anchor path says to review `list_files` for "files this build doesn't produce" — **do not** put those four into a delete plan.
- **Tokens export via `tokens/tokens.css` as of 2026-07-31.** Before: `tokenFiles` was empty (no tokensPkg), so `emitReadme` fell back to scraping every custom-property declaration out of `_ds_bundle.css` — the project README's `## Tokens` listed 133 "tokens" including `--tw-*`, `--animate-spin` and `--default-transition-*`, and classified `--tw-inset-shadow` as *spacing* (reported by the design handoff). Now `ds-css/build.ts` also emits `frontend/.ds-css/tokens.css` — the top-level `:root`/`.dark` blocks of `styles/globals.css`, verbatim, comments included — and `cfg.tokensPkg: ".."` + `cfg.tokensGlob: ".ds-css/tokens.css"` point the converter at it (`tokensPkg` is joined onto `--node-modules`, so `..` = `frontend/` itself — the only way to name an app repo with no separate tokens package; cosmetic casualty: the README's Tokens intro reads "from ..", the count is 45). The Tailwind internals still exist inside `_ds_bundle.css` — they are functional (utilities compose through `--tw-*`) and must not be stripped; the fix redirects the token *export*, not the bundle. `styles.css` now imports `tokens/tokens.css` before `_ds_bundle.css`: duplicate identical declarations, the bundle still wins the cascade, no render change — component grades carry.

- `DetailPanel`, `FilterRail` (+ `FilterGroup` sub-part) and `FilterSelect` became kit cards 13–15 (2026-07-31, Alerts-redesign sync): the app's dependency-cruiser rule moved them from `features/explore` into `components/ui`, and the user scoped all three in — **explicitly reversing the 2026-07-27 exclusion of FilterSelect** (it was app-glue then; it is kit by location and reuse now). DetailPanel mirrors Resizable's override (`cardMode: "single"`, `primaryStory: "ListAndDetail"`, `viewport: "720x360"`); the other two need none.
- **FilterRail and DetailPanel are dark-committed chrome**: they hardcode navy hexes (`bg-[#0B1826]`, `border-[#17293D]`, …) because the app pins itself to `.dark`. On the light theme (the previews' default) their foreground text sits dark-on-navy and is unreadable — with a perfectly CLEAN render check (0 errors, healthy PNG bytes): another "renders ≠ readable" case, same family as the collapsed Resizable panel. Their previews wrap every story in `dark bg-background text-foreground`, and both docs tell the design agent to use them under a `class="dark"` root. Don't "simplify" the wrapper away.
- `--state-solved` token added 2026-07-31 (light `#2E7D4F` — same unrendered caveat as the other light steps — / dark `#5FB37C`): the one success green, deliberately not `--primary` (brass = brand/interactive, never "good news"). Conventions enumerate `text-state-solved` / `bg-state-solved` (both compiled from app source — StateBadge and the episode timeline use them) and the kit count line reads fifteen.

## Conventions ↔ safelist coupling (verified 2026-07-28)

The validation pass greps every class the conventions header names against the compiled `_ds_bundle.css`. On the 2026-07-28 re-sync it caught three classes — `bg-muted`, `justify-end`, `font-bold` — that `conventions.md` had named since the first sync but which were **never compiled**: no app source or preview uses them as bare classes, and they weren't in `frontend/ds-css/entry.css`'s `@source inline()` safelist. Pre-existing drift, not caused by that run's changes (`git grep justify-end HEAD -- frontend/src` was empty). Fixed by adding all three to the safelist. Lesson: any class the header enumerates that the app doesn't itself use MUST be safelisted, or the design agent writes a class that resolves to nothing.

## Known render warns

- `[FONT_REMOTE] "IBM Plex Sans", "IBM Plex Mono"` — legitimate: the brass theme loads Plex from Google Fonts at runtime; verified rendering correctly in headless capture (2026-07-27).

## Re-sync risks

- **Compiled-CSS snapshot**: `_ds_bundle.css` only contains utilities scanned from `frontend/src` + `.design-sync/previews` at `buildCmd` time. New previews or app code using new utilities need `buildCmd` re-run before the converter, or the classes silently miss. When in doubt, always re-run `buildCmd`.
- **Conventions drift**: `.design-sync/conventions.md` enumerates classes/tokens — re-run its validation (grep against fresh `_ds_bundle.css` + component dirs) on every re-sync; app refactors can drop utilities from the scan.
- **shadcn upstream refresh**: `frontend/src/components/ui/*.tsx` are vendored shadcn code — a regeneration (e.g. `npx shadcn@latest`) changes render hashes and correctly triggers re-verify of everything. **Specific casualty to check after any regeneration: the `dark:data-[state=checked]:bg-primary` class in `checkbox.tsx`** (see the bullet above) — it looks redundant, upstream's ordering may not include it, and losing it silently kills the checked fill in dark mode. The render check will NOT catch it: the card still renders, just without the brass fill. **Second casualty: the `ResizablePanelGroup as Resizable` alias in `resizable.tsx`** — validate does catch this one (`[BUNDLE_EXPORT] … not a component on window.Bugler`), same as `Chart`.
- **Recharts is a real runtime dependency of the kit** (added 2026-07-29, v3.10.1), unlike every other primitive which is vendored source. A Recharts major bumps the bundle from ~200 KB to ~1.4 MB territory and can change `Chart`'s render without a single repo file changing — if `Chart`'s card looks wrong after a dependency update, that is the first suspect. The seven re-exported marks are also a version surface: names that move upstream break `previews/Chart.tsx` and every app chart at once.
- **Toolchain assumptions**: bun 1.3.x + bun-plugin-tailwind (repo dep) build the CSS; node 24 + npm-installed esbuild/ts-morph/typescript@5/playwright@1.62.0 (`.ds-sync/`, regenerated per clone) run the converter.
- **Remote fonts**: IBM Plex loads from Google Fonts at render time — an offline headless capture silently falls back to system fonts and screenshots will look subtly wrong without any warn beyond `[FONT_REMOTE]`. Grade font-sensitive changes only with network available.
- **Grades**: verification state lives in the uploaded `_ds_sync.json` (project) and gitignored `.cache/` — a fresh clone re-verifies only what the anchor can't vouch for.
- **Adding a kit primitive** is a five-part change, and missing any one of them ships a half-imported component: `cfg.componentSrcMap.<Name>`, an authored `.design-sync/previews/<Name>.tsx`, a `.design-sync/docs/<name>.md` with `category:` frontmatter (the group), an `cfg.overrides` entry if it's an overlay or wide, and the enumeration line in `conventions.md`. The converter will happily emit a floor card for a component that has only the first.
- **CRLF drift on freshly-authored docs** (seen 2026-07-28): `core.autocrlf=true` on this machine, and `.design-sync/docs/*.md` carry no `.gitattributes` override. A doc authored in-session is LF on disk, so the `<Name>.prompt.md` built from it uploads LF; after it's committed and re-checked-out it becomes CRLF, and the NEXT re-sync reports that component as `changed` with only its `prompt.md` sourceHash moving. Content-identical, self-correcting after one upload — confirm with a `get_file` diff before chasing it. Combobox/Dialog/FilterChip took exactly this path on the 2026-07-28 cursor-fix sync.
- **Conventions drift is silent by construction**: nothing fails when the header names a class that isn't compiled — the design agent just emits dead classes. Re-run the grep of every enumerated class/token against the fresh `_ds_bundle.css` on every sync (see the coupling section above); it is the only thing that catches it.
- **The token export silently reverts if `frontend/.ds-css/tokens.css` is missing** (converter run without `buildCmd`, e.g. on a fresh clone): `copyTokens` finds nothing and `emitReadme` falls back to the polluted bundle scrape — no error anywhere. Checks: the build log prints `tokens: 1 files from ..@…`, and the README `## Tokens` count is ~45, not 100+. The extraction in `ds-css/build.ts` also assumes `globals.css` keeps top-level `:root {` / `.dark {` blocks closed by `}` at column 0 — it exits 1 if either block is not found, so a globals refactor fails the build loudly rather than shipping an empty token file.
