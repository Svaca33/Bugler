# The policy stops scripts and lets styles through

Every response on the App surface carries a Content-Security-Policy, `X-Content-Type-Options: nosniff` and `Referrer-Policy: same-origin`. The policy refuses scripts from anywhere but Bugler itself, refuses framing outright, and admits inline styles on purpose.

Rendering text somebody else wrote is not an edge case in Bugler, it is the product: every Log Record body, attribute key and span name on screen arrived from a monitored application. No XSS exists today — telemetry reaches the DOM as React text nodes, which escape — but a policy is not for the XSS a codebase has, it is for the one a later change introduces, and the candidates are not exotic. Making URLs inside a Log Record clickable is the most ordinary request a log viewer ever receives and precisely where a `javascript:` href gets built; rendering a body as highlighted JSON or as markdown is the next one; a compromised dependency needs no feature at all. What one would cost is worth stating plainly, because `HttpOnly` does not cover it: a script running inside the page never needs to read the Session, it issues requests and the browser attaches the cookie itself. An Admin who opened the wrong Log Record could have Applications deleted — Deletion being irreversible and never partial — API Keys issued, or Users created, by their own hand as far as the server can tell.

`script-src 'self'` is the half that does that work, and it cost nothing to adopt: the built `index.html` carries no inline `<script>`, no inline `<style>` and no event-handler attribute, only external hashed chunks.

`style-src` keeps `'unsafe-inline'`, and this is the part a reader will come to undo. Radix's Dialog and Select reach the DOM through react-remove-scroll, which appends a `<style>` element to the head every time either one opens — thirteen files under `frontend/src/features` mount one. Under a strict `style-src` the browser refuses those elements, and the failure is a layout shift and a console line, in the browser, on a screen nobody's test opened. What tightening it would buy is small in a way worth being precise about: an inline style executes nothing, and the only way CSS exfiltrates what it can see is by fetching — which `default-src 'self'` already refuses. It would rule out an injected style repainting the page, and that is all.

`font-src` admits `data:` because IBM Plex is now served by Bugler rather than fetched from Google, and Bun inlines the faces into the stylesheet as data URIs with no documented way to prevent it. A font executes nothing, and `data:` stays out of the directives where it would matter.

The headers are written by one middleware inside the branch that already gates the static files on the App surface, so they reach the SPA document, the bundles, the REST answers and the 404s alike. A rule with no exceptions cannot be missed by whoever adds the next endpoint, and `nosniff` earns its place on the REST answers most of all: a JSON body full of telemetry is a better thing to have read as HTML than `index.html` is.

Worth being clear about the limits, so this is not mistaken for more than it is. A policy does not repair an XSS, it bounds one. And only browsers enforce it, so it speaks for the UI alone and says nothing about the REST API or the OTLP surfaces, where the callers are not browsers at all.

## Considered Options

- **A nonce, so `style-src` could drop `'unsafe-inline'`.** The path exists: react-remove-scroll reads one through `get-nonce`. Rejected for what it costs against what it buys. A nonce must be fresh per response and present in both the header and the document, so `index.html` stops being a static file served by `MapFallbackToFile` and becomes a template rendered per request, marked `no-store`, with the value carried into the SPA's boot to be handed back to the library. That is a real change to how the UI is served, in exchange for ruling out repainting — see above for why that is the whole of it.
- **Report-Only first.** The usual advice, and it assumes somebody is collecting reports. Nobody is: there is no reporting endpoint, self-hosted operators would not stand one up, and a policy nobody reads reports from is a policy that is never enforced. The exposure was measured by reading the build instead — no inline script, one `<style>`-injecting dependency, one external origin — and all three were dealt with directly.
- **Keeping Google Fonts and naming them in the policy.** One line cheaper than self-hosting. Rejected because it writes a third-party CDN into a security policy for something that was already half broken: a Bugler inside a closed network could never reach `fonts.googleapis.com`, so the typography there quietly fell back to system faces after waiting for a timeout to say so. Self-hosting fixes that as a side effect, and stops every page view telling Google who is looking.
- **Serving the fonts as files rather than data URIs.** Preferred, and not available. Bun inlines small assets referenced from CSS `url()` and exposes no threshold; `loader: { ".woff2": "file" }` does not reach inside CSS, and a root-absolute `url()` or `<link href>` fails the build rather than passing through. The remaining route — copying the files after the bundle and splicing a `<link>` into the built HTML — was rejected for making `globals.css` stop describing the typography that actually ships, and for having no counterpart in the dev server.
- **A configurable policy.** Rejected on the ground ADR 0019 already stands on: a knob whose easiest setting is the permissive one. An operator who needs a different policy has a reverse proxy in front and can replace the header there.
- **Headers on the served documents only,** through `StaticFileOptions.OnPrepareResponse` and the same options passed to `MapFallbackToFile`. Rejected for being two configurations that must agree and one day will not, and for leaving the REST answers — the ones carrying telemetry — without `nosniff`.

## Consequences

- **`'unsafe-inline'` in `style-src` will be reported as a finding** by any scanner pointed at Bugler, and it is not one. Removing it breaks every Dialog and Select in the product, silently. This paragraph is the answer to that report.
- **A reverse proxy must not add a policy of its own.** A browser given two enforces their intersection, so a second policy that merely looks stricter subtracts from this one and breaks the UI. `DEPLOYMENT.md` says so where the proxy is configured.
- **The first load carries the fonts** — the stylesheet is 14 kB gzipped without them and 350 kB with. In exchange it drops three serialised round trips to two third-party hosts that a remote `@import` used to spend before a single glyph arrived, and deployments with no route to the internet get the typography they were designed with for the first time.
- **The chart kit lost `ChartStyle` and the `theme` branch of `ChartConfig`.** The `--color-<series>` properties are set through React's `style` prop, which reaches the CSSOM and is therefore outside the policy's reach — and, more to the point, no longer composes markup out of a config key. Nothing here used the `theme` branch: a Bugler chart colour is a `var(--…)` and the token underneath it is what answers to light and dark.
- **Nothing exercises the policy in a browser automatically.** The Playwright suite runs against the dev server on :3000, which serves its own HTML and sends no headers, so a future inline script would pass CI and fail on :8080. Verification is manual, on the redeployed container, until the e2e suite is pointed at the production shell.
- **A feature needing a new origin now has to say so.** An avatar host, an embedded map, a telemetry link that loads anything — each would fail closed, in the browser, and the fix is an edit here rather than a shrug.
